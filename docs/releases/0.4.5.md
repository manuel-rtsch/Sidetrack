Sidetrack 0.4.5 closes the last keypad gap and makes the audible row visible. Every one of the four keypads now opens Search and Playing Now, and a list says which row is playing and where it has got to. The queue no longer loses a dragged row to its own data changes, and first run draws the keypad the way the hardware prints it. Sidekit 1.13.1 supplies the keypad work the corner holds stand on.

## Keypad

- **The Sundial's two upper corners reach Search and Playing Now on every row.** Held **←** opens **Search** and held **→** opens **Playing Now** — on the list rows *and* on the Library's category row, where the arrow reservation used to stand down the corner holds and a held key just slid across the filters. A short tap still moves one step.
- **A held Enter always lands focus in a bar.** On the Sundial it opens the screen's options when the screen has any, and falls back to the main action bar when it has none, so there is no dead hold on a screen with an empty options menu.
- **The game controller's Y key opens Now Playing.** The action bar stays reachable through the X hold (Options), leaving Y free for the now-playing surface instead of a bar you could already reach another way.
- Sidekit 1.13.1 is the keypad foundation: the corners' Search and Playing Now holds, held Enter, and the held-arrow reservation that lets a screen's own gesture win over a chrome hold.

## Rows

- **A list names the row that is playing.** The audible row carries the explicit badge's chip — on the cover, or in the track-number lane where the page has no artwork — and the row itself says **Playing** or **Paused** to a screen reader, so TalkBack gets the state the silenced chip cannot say.
- **The playing row runs a progress line.** Four wide along the row's own lower edge, accent while it plays and muted at its frozen offset when paused — the same language a podcast row already uses for where you stopped. It is the only thing on a list that listens to the seek clock, so the tick reaches one small composable instead of the list.
- **One mark per row.** An item row wears the progress line (its chip was the redundant half next to the line), a collection row keeps the chip on the cover, and track numbers and a paused episode's resume line are untouched.
- **The marks stay readable.** The line sits at the row's edge instead of driving the title, and the corner arc swallows the line's ends so nothing pokes past the frame.
- An album row that was audibly playing no longer offered an idle **Play**: the queue now remembers where it came from, so the play tile asks the origin instead of guessing from the items it holds.

## Queue

- **A drag knows which row it lifted.** Every queue entry has a stable row identity across the reorders a drag itself causes, so the lifted row stays under the finger instead of swapping place with a sibling mid-drag.
- **The lift owns the viewport.** The list holds still while a row is held, auto-scroll commits each move as it lands and stops cleanly at the slot, and a drag ends only from the gesture that began it — the queue no longer drops a row where another event was interrupted.

## First run

- **The keypad guide draws the module in your hand.** Caps show what they print — a glyph on CALL, END CALL, Home, Delete, Enter, Search and the D-pad, **Y / X / B / A** on the controller's face, a dash on the blank caps — while the translated name and its tap-and-hold actions live in a detail card that grows to fit. The mini QWERTY folds to its real five hardware keys, and the controller keeps its five-column shell. Welcome and Settings > Keyboard now share Sidekit's renderer, so Sidetrack's copy is gone.

## Options

- **Now playing stays only where it is the fastest way in.** A content screen keeps the entry (two taps without giving up the screen underneath), song radio and artwork drop it — their Back already opens Now Playing in one press — and a playlist page that offers Rename or Delete drops it to give the bar width. A read-only playlist keeps it, as an album does.

## What stays the same

Package, signature and certificate are unchanged, so the app updates in place and keeps its history, queue, resume point, settings and search history.

## Under the hood

- Sidekit 1.13.1 replaces 1.13.0. The queue file is now version 3, carrying each queue entry's origin (set by play, cleared by the queue edits, read as null from versions 1 and 2).
- The corner holds needed a hold a screen can own: `ChromeState.reserveHold` lets the Library's held-arrow category step win on the list rows while the native corners keep working above them.

Sidetrack 0.4.2 is the round that makes the queue your own: a row tap on an album no longer
silently throws away what you had lined up, and when it does, it offers the old queue back for a
few seconds. Plex joins as a fourth service, Navidrome grows into the whole Subsonic family, and
playlists can be renamed and deleted. Nothing needs reinstalling — same package, same certificate,
so it updates in place.

## Queue

- **Play one track without losing the queue.** Album, playlist and radio rows gained a **Play**
  action that plays that track now and hands the rest of the queue back afterwards, so hearing one
  song is no longer the same gesture as replacing everything. Shuffle, Repeat context and the
  pre-shuffle order all survive it, and the track is moved rather than played twice if it was
  already further down. The row tap still plays in collection context, which is what Next,
  Previous and Repeat context are defined by.
- **A replaced queue can be taken back.** The row tap that does replace the queue now shows
  `Queue replaced | Undo` for eight seconds. Undo restores the previous queue and resumes the
  interrupted item at the offset it left off. Any other play, dismissing the bar or the deadline
  withdraws it, and Undo re-checks that the tapped item is still playing, so a stale offer can
  never undo a newer choice. History keeps the listen it earned — the offer gives back the queue,
  not the listening.
- **Later pages join the queue that is already playing.** Starting an album whose next page is
  still loading no longer leaves the queue with one page in it: the pages behind "See more" are
  appended as they arrive, and only if that page is still what the queue is playing.
- "Add to queue" has its own glyph now, so it no longer shares one with the queue screen itself.

## Playlists

- **Rename and delete.** Both are permissions of their own, per playlist, alongside add and remove
  items: a service can allow one without the other, and a collaborator may add tracks without
  owning the list, so an entry only appears where the server agrees. Destructive entries sort last
  and wear the destroy tone.
- **New playlists seed from what you played.** The create form starts from recent tracks instead of
  an empty list, still keyed by track rather than row, so a changing recent list cannot shift what
  the form is about to create. A pasted paragraph is cut at the length a row can show instead of
  becoming a name nothing can render.

## Search

- **Search has a landing page.** The field starts on its own page with the recent terms under it,
  and submitting splits into the results screen, so leaving and returning no longer loses the
  query or the scope you were in.
- **Terms persist.** The last 20 searches are kept newest first, a repeat moves to the top instead
  of appearing twice, and a term under the two letters a search needs is not stored. Individual
  terms can be removed.
- Holding Left or Right still switches scope and restores the row and scroll it was left at.

## Plex

- **Plex is a service.** Sign-in is a PIN exchange with plex.tv, so the Plex password never reaches
  Sidetrack; the token lives in the same encrypted, write-through store as the other services.
  Music libraries, playlists, artists, albums, search, playback progress and scrobbling are all
  wired; liked/saved is Plex's own rating convention.
- **What Plex does not offer is hidden, not broken.** No radio endpoint, no loudness parameter, no
  gapless handoff, and playlist creation needs a non-empty item URI — so the create form is left
  out instead of failing on submit. Rename and delete are supported.

## Subsonic family

- **One adapter, three names in the picker.** The Navidrome module became `:provider-subsonic` and
  serves Navidrome, Nextcloud Music and Subsonic, which speak the same API. Each entry keeps its
  own credentials, queue, history and resume point, so signing into two servers keeps two
  libraries.
- **The picker is alphabetical** and lists every entry where you would look for it.
- **Navidrome installs upgrade in place.** The id, the encrypted store name and the local queue,
  history and resume file names are unchanged, so an existing session is simply signed in.

## Playback

- **A track the service refuses is skipped, not retried.** Spotify answers an unavailable item and
  moves on internally; the app used to stay on it, read the silence as a dead access point,
  rebuild the session and reload the same track three times before giving up. It now advances the
  queue the way a finished track does — autoplay included, and never with Repeat track — and says
  so only when the queue really moved.
- **Live players stay live.** A finished track is no longer reloaded, and the player is kept across
  the transitions that used to rebuild it.
- **A rolling playback log** records what the engine and the session did, with stable event names,
  so a report about a stall or a skip can be read instead of guessed at.
- **Sleep timer wording follows what it does:** "Pauses in 23 min", "Pauses after this track",
  "Paused by sleep timer". Home's one-line eyebrow now says `TIMER DONE` when the timer finished —
  the previous wording was ellipsized in that slot.
- **Episode notes are readable from the keypad**, and podcasts have their own Now Playing card.

## Menus, rows and appearance

- One factory builds every Options bar and row action menu, so the same entry no longer changes
  label, glyph, shape or colour per screen. Colour follows what an entry does: accent for live,
  green for on, red for destroy.
- Every list shares one row identity and one gutter body, which is why search results and library
  rows behave the same way.
- Appearance keeps Sidetrack's own settings editable behind a Sidekit host, and the backdrop row
  was shortened so its value fits.

## Under the hood

- **One Media3 service runtime** for the Subsonic family, Jellyfin and Plex: the media session,
  notification, audio focus and resume rules can no longer drift between services. Jellyfin and
  Plex also share one playback-reporter state machine.
- **AGP 9.5.2 with compile SDK 37.2**, Gradle 9.9.2, Sidekit **1.11.0**. The keypad detection and
  the text-field keyboard, action and focus handling the app relies on live in that SDK.
- **Releases can no longer ship a native-less APK.** A tag now builds the librespot bridge and
  both APKs, and three gates refuse to publish without it: one before packaging, one that reads
  the packaged APK, and one that checks the signature, package, version and ABI set of the
  artefact. The About screen also states which Spotify engine the installed APK carries.
- **The version is derived once** from the checkout, in `buildSrc`, and the version code is the
  commit count, so an upgrade is never refused.

## Upgrading

- **In place, no uninstall.** Package, signature and version-code chain are unchanged — the code
  only ever grows, because it is the commit count — so an existing installation is updated and its
  data directory is kept. History, queue, resume point, local settings and the search history keep
  their file names.
- Sidekit is taken from the published release, exactly as the version catalog pins it.

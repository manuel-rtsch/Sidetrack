Sidetrack 0.4.4 rebuilds the three screens you meet first — setup, About and the artist page — around the keypad rather than adapted to it, and gives every prompt in the app one shape. Under that, the player stops claiming things it cannot know: a start that failed no longer reads as a pause. This is also the first release that ships a single APK. Package, signature and certificate are unchanged, so the app updates in place.

## Setup

- First run is three pages: **Keypad**, **Keypad guide** and **Make it yours**. The step is remembered, so an app killed mid-setup resumes where it stopped instead of at the beginning, and the keypad Back key walks back through the pages. Help reuses the same body.
- A new **Keypad layout** page, reachable from setup and from Keypad settings: picking a module applies it to the attached keypad, or fixes the custom mapping when one is active. It replaces a row that cycled to the next layout on each press, which meant finding out what you got after the fact.
- The guide between the first two steps is interactive: Sidekit's key rows, with a detail card that grows to fit the tap-and-hold text instead of clipping it.
- Where Sidetrack prints a module name it now says Gamepad. Appearance and Audio quality take the name of the page that opened them, so Back reads correctly from setup, where those pages are not the ones you came from.

## About

- The page is settings rows instead of cards. **Version** reveals the build details, Author, Source code and Sidekit open their GitHub pages, and Licences toggles a table that starts folded.
- Every card is a focus stop and performs something, with the first one focused on entry. Version used to be the only target, so the D-pad could not move through the page and Sidekit's list could not scroll to the licences.
- The Sidekit link points at the fork Sidetrack builds against, and the licence table credits Harlan Postill upstream.

## Artist pages

- A Spotify artist gets **All songs**, behind the Top tracks label. The service's top-tracks endpoint returns ten rows and ignores the offset, so Load more could only ever repeat page one; the rest of the discography was reachable an album at a time.
- The page walks the artist's albums in the service's own order and flattens them into one stream, dropping repeats by track id, because an album, its singles and a compilation carry the same song. Twenty rows per press, and **Load more** appends rather than starting over.
- The play tile queues the catalogue, not just the rows that have arrived: the pages behind Load more still extend the tail, so the queue matches the list once they do. Back returns to the artist.
- Only the services that need it get the link, which today means Spotify alone: everywhere else the top list is already the whole catalogue, so a second page would be one press to the same rows.

## Rows

- The duration is formatted for a list rather than a player. It keeps the exact `75:30` form below 99 minutes and only then trades the seconds for `1h 40m`, where the old hour form widened the trailing column and pushed every title on the screen left. Seek and the podcast readout keep their seconds, where the seconds are the point.
- The duration sits a step down in weight in tabular figures, and the explicit marker is a chip in the artwork's corner instead of text trailing the artist as `· E`, where it read as part of the name. Both stay described for a screen reader.
- The track-number column holds two digits in 30 dp, and a three-digit index drops to a dense style rather than widening the column for the one album that reaches 100.
- A row's height is solved from the fraction of the next row that should show instead of taken from a token: 4¼ rows on the spacious layout and 5¼ on the compact one. At the old 104 dp the fold sat exactly on the fourth row's bottom edge, so the list read as complete when there was more.
- An artist page names the track's album under the title instead of repeating the page title, and search drops the duration, which is not part of choosing a result.

## Prompts

- Every prompt is one bar: the decision on the left, a close square on the right, told apart by tone — grey and rising to restore, red and phrased as a question for an edit that cannot be taken back, grey for a notice. The square never changes the world and holds the cursor, so Enter is always the press that changes nothing.
- Undo is one convention: grey, the undo glyph, rising in place, labelled **Undo** and described as "Undo <the edit>". A restore names its inverse — "Restore queue", "Restore Sultans of Swing" — instead of saying Undo where the object is gone. Adding a track to a playlist is a creation and reports "Added track to <playlist>", so its Undo is gone.
- Clearing the cache asks first. The row used to clear on one press and say nothing at all. It cannot be undone by anyone, so the question is red and the square cancels.
- Renaming a playlist offers **Restore old name** for a few seconds, since retyping a name on a keypad is the expensive part. Removing one remembered search term is announced (`Removed "night"`) rather than offered back, because it is one keystroke to type again.
- A confirmed press no longer gets a receipt for the same act — "Cache cleared" after "Clear cache?", "Removed … from Road Trip" after the removal question. The failure branches keep their words, because that is the one outcome the question could not promise.
- The cursor comes back. A prompt is opened by key in one call rather than by jumping to a slot and moving a frame later, and when it closes the page's element is focused again — or, when the edit removed the row for good, the row that took its place.
- The playlist picker and the new-playlist form no longer offer the now-playing confirmation, which was live for a few seconds while its leading art button did nothing and the Back it replaced was gone.

## Playback

- The player tells starting apart from paused. A source still resolving shows **STARTING** with the record turning, and a start that ended without audio says **COULDN'T PLAY**; both used to fall back to "paused", which claimed something had been interrupted when nothing had started.
- Pause and stop work before a player exists. A volume-down during a slow handshake failed with `PLAYER_NOT_CREATED`, which turned a recoverable race into a playback failure; both commands describe "be at rest", and a session without a player already is. Play, seek and load still require a player, having nothing to act on without one.
- Giving up on a connect no longer gives up on the connect. The wait wrapped a blocking call that could not be cancelled, so a 25 s timeout returned after 31 s and the recovery dialled the access point a second time. The pass now runs on its own and only the wait is bounded: the next caller joins the attempt in flight, and a pass that finishes late leaves the session connected for the retry.
- A rotated Spotify OAuth token no longer rebuilds the session. A librespot player is bound to the access-point credential it received at connect, so the rebuild dropped the player and the gapless handover underran its audio track. A rotated token is a separate answer now: it is stored for the catalogue calls and the session keeps playing.
- A radio request settles on the attempt's identity, so a station that ended without a result — cancelled, or superseded by another seed — no longer leaves the screen spinning forever with nothing left to write the state it waits for.
- Clearing the cache has a failure path: it runs through the same in-flight registry as other work, so a cache that cannot be cleared says so instead of looking cleared.
- A status block is one announcement for a screen reader: the title is what it is, the hint is its state, and a load that starts or fails after focus landed is still spoken. TalkBack used to read the record's description and then the same title again.

## Lists and loading

- Library, Search, Add to playlist and the collection routes share one first-load ladder — record, title, hint, Try again — so the four cannot drift apart. A screen with a transient nothing-yet state renders nothing instead of an empty page.
- A search's first load names the query instead of showing a text row, and a load that runs past eight seconds says "Still loading" rather than turning silently.
- A cover that failed to fetch gains **Try again** and re-runs under a new key; a known-missing cover still has nothing to retry.
- Signing in shows the record while the attempt is live, named per mode: the service for a browser round trip, "Signing in" for a password form, the permission for the device library. The bar stays live, because a second press deliberately supersedes a stale listener, and the form returns with what you typed.

## What stays the same

Package, signature and certificate are unchanged, so the app updates in place and keeps its history, queue, resume point, settings and search history.

## Under the hood

- Sidekit 1.13.0 supplies the public `focusActionBar(key)` and `saveContentFocus`/`restoreContentFocus` the prompt work is built on. The keypad square answers to one key app-wide instead of eight per-site dismiss keys, and every slot carries its own focus requester, so opening a prompt is one call rather than two jumps.
- A transport command now names who asked for it: the platform session binder, the noisy-audio guard, the shared toggle and the end-of-item pause each print before routing. A pause that used to log `pauseInternal abandonFocus=true` and nothing else no longer needs a `dumpsys audio` session afterwards to explain itself, and a command the player never confirmed says so when its deadline lapses.
- In-flight work is tracked by key. Library paging, playlist writes and the cache clear run through one registry, so a superseded page cannot land on top of a newer one, and a failure has somewhere to be reported.
- The providers share one HTTP socket layer, one server-address reader and one playlist-write transport, and the JNI entry points share their argument marshalling.
- CI runs the three variants as parallel jobs instead of assembling them in one, checks ktlint over the whole tree rather than only what `origin/main` changed, pins third-party actions to full commit SHAs, and runs PMD CPD against a recorded duplication budget.

## Builds

| Asset | Notes |
| --- | --- |
| `Sidetrack-0.4.4-arm64-v8a.apk` | The only APK this release ships: arm64-v8a, the SP-01's ABI, about half the download of the old universal build |
| `SHA256SUMS.txt` | Checksum for the asset |

0.4.4 is the first release without a universal APK: every SP-01 is arm64, the app pack can index only one file per `versionCode`, so the second asset was one the pack could never serve. An emulator or an x86_64 phone can still have one from `./gradlew :app:assembleRelease -PsidetrackNative=true` without `-PsidetrackAbis`.

The APK is signed with the same Sidetrack release certificate as 0.4.3 and carries the native Spotify bridge for its ABI, as every release does. The app pack serves this APK.

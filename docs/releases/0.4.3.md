Sidetrack 0.4.3 adds a fifth source: the music already on the phone. Around that, the player and the screens stop guessing: a lost connection no longer silences buffered audio, a failed page says what failed, and it retries itself once the network is back. Package and signature are unchanged, so the app updates in place.

## Local library

- The service picker has a new entry, **Local library**. It reads what MediaStore already indexes: tracks, albums, artists and playlists. Sign-in is one permission dialog, not an account. From Android 13 it asks only for audio access; below that, for the storage permission.
- Every track plays through the shared player, so the queue, history, resume point, keypad and notification work as they do with a server. Artwork comes from MediaStore, including on the notification and the system Now Playing card.
- Liked songs are a list kept on the phone, since the device has no favourite flag. Albums and artists are grouped from one read, so the sections cannot disagree while the phone is scanned.
- Sidetrack's own playlists are `.m3u8` files in `Music/Sidetrack`. They can be created, renamed, edited and deleted, and any other player reads them as a plain playlist. Each carries a comment with a fixed id, so a rename keeps every open page and cached row pointing at the same list. System playlists are listed read-only: Android only lets the app that created one change it.
- Not there, because a file cannot deliver it: radio, podcasts, follow, quality selection, normalisation, gapless playback, scrobbling and server-side progress. Those controls stay in place, dimmed and inert.

## Playback

- Media3 sources — local, Subsonic, Jellyfin, Plex — were driven by a one-second stopwatch, so position, buffering and the end of a track were estimated. They now come from the player's own events. The platform media session carries the real queue, a moving position and audio attributes for local files, so the lock screen and the system card show more than a title.
- A player error on those sources now skips to the next item. Before, it took the Spotify stall path, stopped the player and retried the same track behind “Reconnecting…”.
- A `content://` source plays. The player handed every item to an HTTP data source, so a local file died on “unknown protocol: content”.
- The state the notification shows stays what you asked for until the player confirms it, so a resume after a settings change no longer flashes “paused” for six seconds.
- A paused player no longer shows “Loading” after a seek, and changing the bitrate or normalisation mid-track now says “Audio settings apply when playback pauses” instead of doing nothing visible.

## Spotify

- Losing the access point mid-track now waits for the network instead of dialling into a dead connection. The retry happens once the network reports back, and only if you have not moved on or pressed pause in the meantime.
- A failed connection arms a backoff that doubles from one second to eight, so a flapping connection no longer walks all six access points three times in four seconds.
- Browsing that finds the Spotify session dead rebuilds it without silencing what is playing. The replacement handshake happens first and the old player is swapped out only once it succeeds, then the current item reloads at its position. If the network is still down, the old player stays attached and the buffered track keeps going.
- A failed Web API request now reports the failure. Before, a server error looked like an album with no tracks or an artist that does not exist.

## Offline

- Only a network Android has actually validated counts as online now. A Wi-Fi link that kept its carrier but lost DNS used to report a connection, so offline failures were read as “the service isn't connected” and the fallback was attempted over the same dead link.
- A failed page says what failed. Browsing and playback shared one message, so an unreachable library said “Playback isn't ready”. With no network at all it says “No internet connection”.
- **Try again** is now a button in the action bar, next to Back, instead of a line inside the empty state. The record, title and hint keep the page.
- A page that failed for want of a connection retries itself when the network comes back. Before, only the open library category refreshed.

## Lists and search

- Opening a list shows its first page again. A category or playlist you had paged deep reopened at every page you once scrolled through, so the same screen came up as 20 rows or as 120. Returns still paint from the cache, and the next **Load more** continues from twenty. The add-to-playlist picker is the one exception: it refetches its first page, because its cursor counts catalog rows.
- The **Load more** row shows the same record the splash uses instead of writing “Loading…”, at the size of the row's arrow, while the page is in flight. A screen reader still hears “Loading…”.
- On the search landing screen the hint under **Search in** no longer falls past the edge, cut in half, while the keyboard is up. **Done** below two letters now closes the keyboard and gives back the bar instead of doing nothing silently, and the rule is announced with the field. Section labels are headings for a screen reader, an empty field is no longer announced as “Search, Search”, and the clear-history Undo pauses while the keyboard hides the bar rather than expiring behind it.

## Queue

- Next at the end of the queue now says “End of queue” instead of doing, saying and logging nothing.
- Queueing and adding confirm with the action rather than the track name: “Added track to <playlist>”, “Added track to queue”. The item's title stays in the screen reader's description of the row action.

## What stays the same

Package, signature and certificate are unchanged, so the app updates in place and keeps its history, queue, resume point, settings and search history.

## Under the hood

- The native bridge links one TLS stack again. Seven dependency advisories, one of them high, came from the proxy crate's pinned old rustls; it is now vendored locally against the version librespot already uses, without dragging aws-lc into the NDK build.
- A cold launch records four marks — Application, activity, session and first frame — in the debug log, plus the host read and the graph, so a slow start names its phase instead of only its total.
- Comment prose is cut back to the reason it records across the sources.
- `:provider-local` joins the coverage gates at its measured floors.
